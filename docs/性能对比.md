# 性能对比：Rust 版 vs Python 版

> 同一台机器、同一个 mock CPA、同一份配置，多轮取中位数。
> 复现：`python scripts/bench.py`（路径全部参数化，不写死个人目录）

## 测试环境

| 项 | 值 |
|---|---|
| 机器 | Windows 11 |
| Python | 3.14 |
| Rust | stable-x86_64-pc-windows-gnu |
| Rust 构建 | `--release`（`opt-level=z` + `lto` + `codegen-units=1` + `panic=abort`）|
| CPA 后端 | 本机 mock（127.0.0.1:18317，6 个模型）|
| 轮次 | CLI 5 轮取中位，HTTP 40 次取中位/P95 |

## 结果

| 维度 | Rust release | Python 3.14 | 倍数 |
|---|---|---|---|
| 二进制体积 | **3.59 MB** | —（需 CPython + pyyaml + requests）| — |
| 冷启动到端口可用 | 339.7 ms | 328.6 ms | ~1.0x |
| 空闲工作集 | **5.8 MB** | 29.9 MB | **5.2x** |
| 忙时工作集 | **6.0 MB** | 30.8 MB | **5.1x** |
| CLI `check` 中位 | **18.2 ms** | 259.2 ms | **14.2x** |
| HTTP 请求中位 | **0.67 ms** | 2.66 ms | **4.0x** |
| HTTP 请求 P95 | 16.12 ms | 25.29 ms | 1.6x |
| HTTP 请求 max | 29.3 ms | 29.1 ms | 1.0x |

### Python 那 30MB 花在哪了

```
纯解释器          13.25 MB
+yaml/requests    +19.2  MB    ← 大头在这
+本项目模块         +0.2  MB
```

应用代码本身几乎不占内存，**底噪全部来自运行时和第三方依赖**。
Rust 的 5.8MB 里含全部功能、静态链接的 sqlite。

### debug vs release（Rust 内部对比）

| | debug | release | 收益 |
|---|---|---|---|
| 体积 | 111.9 MB | 3.59 MB | 31x |
| CLI check | 30.7 ms | 18.2 ms | 1.7x |
| 工作集 | 9.2 MB | 5.8 MB | 1.6x |

## 三个值得记的结论

**1. 冷启动居然持平（~330ms），瓶颈不在语言运行时。**
卡在 OS 端口绑定和首次 CPA 连接探测上，不是解释器加载。真正拉开差距的是**重复执行的命令**——CLI 差 14.2 倍，因为 Python 每次都要重新 import 那 19MB 依赖。

**2. 常驻服务看工作集，一次性命令看 CLI 耗时。**
面板是常驻的，5.2x 的内存差就是长期收益；CLI 14.2x 主要吃的是依赖加载，不是业务逻辑本身更快。

**3. 尾部延迟更值钱的指标是 P95，不是中位。**
中位 4x，但 P95 只有 1.6x。Python 的单线程 GIL + 调度在压力下尾部抖动更大，max 却持平（都被网络 IO 兜底了）。

## 复现方法

```bash
# 全自动探测（找 target/<profile>/cpa-sync，找项目根 web/app.py）
python scripts/bench.py

# 指定构建类型和路径
python scripts/bench.py --profile debug \
    --rust ./target/debug/cpa-sync.exe \
    --py-src /path/to/python-src \
    --config config/cpa-config.yaml

# 只测 CLI，不起 web（更快，适合 CI）
python scripts/bench.py --no-web --cli-rounds 10
```

完整结果落在 `target/bench-result.json`。

### 已知的测量注意事项

- **不要用 32 位 `GetProcessMemoryInfo` 采样 64 位进程**，返回值会错得离谱（83KB / 114KB 这种量级）。Windows 上走 `Get-Process.WorkingSet64`，Linux 走 `/proc/<pid>/status` 的 `VmRSS`。
- **tar 解包要防 `__pycache__`**：tar 保留 mtime，旧 `.pyc` 可能比新源码"新"，Python 直接用旧字节码，表现为"改了代码没生效"。
- **PowerShell 重定向会被文件锁挡住**：目标文件正被读时写不进去，旧内容留着，表现为"重跑结果没变"。换文件名最省事。
