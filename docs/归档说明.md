## 一、项目是什么

cpa-sync 是 **CPA（CLIProxyAPI）配置同步工具**，把中心 CPA 的模型/配置下发到各机器的 agent（omp / dsh / crush / openclaw / hermes / pi / codex / claude / opencode / picoclaw），并管理 CPA 节点、提供 Web 控制面板 + nginx 网关。

## 二、最终架构（归档时）

**主线 = Rust**（Python 版已归档到 `old/`）：

```
rs/src/
├── main.rs          # 入口：CLI + axum Web 服务（ServeDir 静态）
├── cli.rs           # CLI 子命令：check/models/list/apply/doctor/sync/probe
├── api.rs           # Web API（22 端点）+ 配置读写 + 探测缓存
├── core/
│   ├── config.rs    # 三层优先级：model_overrides > image_models > default_input_modes
│   ├── cpa_client.rs
│   ├── remote.rs    # RemoteIO：本机/远程（ssh/scp）统一
│   └── probe.rs     # 按 cc-switch 源码真实路径表探测（家目录+点目录）
└── adapters/        # 12 个 adapter，全部同构（Rendered{Json,Yaml,Text}）
    ├── omp.rs       # enabledModels 深度裁剪（模型级白名单）
    ├── codex.rs / claude.rs / opencode.rs / pi.rs / dsh.rs / crush.rs
    ├── openclaw.rs / hermes.rs / picoclaw.rs / ccswitch.rs
    └── factory.rs / base.rs / mod.rs
```

**关键技术点**：
- 识图三层优先级：`model_overrides.input`（最高）> `image_models` 通配符 > `default_input_modes`（兜底）
- `RemoteIO` 统一本机/远程：host 有值走 ssh/scp，无值走本机文件——任何 adapter 同构
- omp `enabledModels`：模型级白名单（Glob `provider/modelId`），写入 config.yml 保留其它字段
- probe：按 cc-switch 源码路径表（`~/.claude`、`~/.codex`、`~/.config/opencode`、`~/.openclaw`、win `%LOCALAPPDATA%\hermes` 等）判断目录存在
- probe 结果缓存：`config/gateway.yaml` 的 `gateway.probe_cache`（按 host），前端手动触发

**Web 面板**：`web/static/index.html`（纯原生 JS，无框架无构建），5-Tab 功能内聚卡片流，Rust `ServeDir` 直 serve。

**网关**：`web/nginx.conf` + `cpa-sync-nginx`——单进程 nginx（`worker_processes 1` + `master_process off`，约 2.8MB）聚合多 CPA 上游。

## 三、两套工具分工

| 工具 | 模式 | 用途 |
|---|---|---|
| **cpa-sync** | 中心模式（SSH 下发） | 中心配置 → 各机器 agent |
| **agent-sync** | 客户端模式（本机自拉） | 本机 agent 从 CPA 拉模型 |

共用 `adapters/` 渲染逻辑。

## 五、性能（Rust vs Python，归档时）

- 内存：Rust 9.9MB vs Python 32MB（省 69%）
- 体积：Linux x86_64 4.0MB / aarch64 3.7MB / macOS x86_64 3.4MB / aarch64 3.0MB（stripped + opt-level z + lto）
- 4 平台产物 CI 全绿（全 Linux 交叉编译，macOS runner 只做 9 秒 ad-hoc 签名）

## 六、CI 要点

- 全 Linux 交叉编译（免费无限）：linux x86_64 原生 gcc / arm64 cargo-zigbuild / macOS osxcross 两架构
- 产物分开上传，不 lipo（Linux 无 lipo，避开最大坑）
- 签名：macos-latest runner 只做 `codesign -s -`（ad-hoc），约 9 秒/次
- 全流程 actions/cache（osxcross target+SDK、cargo registry+target）
