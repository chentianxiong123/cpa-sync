# cpa-sync 使用技巧

日常操作、配置心智模型、踩坑记录、扩展要点。README 讲"是什么"，这里讲"怎么用好"。

## 0. 一分钟心智模型

```
config/cpa-config.yaml (唯一事实来源)
   │  cpa.* 全局段
   ▼
/v1/models 扫模型 → include/exclude 过滤 → model_overrides 覆盖 → IR
   ▼
adapters/<name>.py: load_current → diff → render → write(自动备份)
   ▼
各 agent 配置文件（pi / omp / opencode / claude / codex / dsh / picoclaw / crush / openclaw / hermes）
```

**三个关键认知**：

1. **改产物没用** —— `~/.pi/agent/models.json` 是生成物，手改会在下次 `apply` 被 `strategy: replace` 覆盖。要改就改中央配置或 adapter。
2. **能力靠声明，不靠探测** —— CPA 的 `/v1/models` 只返回 `id/object/created/owned_by`，**没有能力字段**，所以"模型能不能识图"只能写在中央配置里。
3. **先 check 后 apply** —— `check` 是干跑，只对比不写。

## 1. 命令速查

| 命令 | 作用 | 副作用 |
|---|---|---|
| `./cpa-sync models` | 扫 CPA 当前暴露的全部模型 | 无 |
| `./cpa-sync list` | 各 adapter 当前状态 | 无 |
| `./cpa-sync check [adapter...]` | 干跑对比（含字段级 diff） | 无 |
| `./cpa-sync apply [adapter...] -y` | 真正写盘（自动备份） | 写 |
| `./cpa-sync sync [adapter...] -y` | 交互式向导 | 写 |
| `./cpa-sync doctor` | 诊断连接 / 配置 | 无 |
| `./cpa-sync-gui` | PySide6 图形界面（复用 CLI 全部 `cmd_*`） | 视操作 |

`[adapter...]` 可省略 = 全部；也可写多机接入点。写盘前建议先 `check`，看 diff 再 `apply`。

## 2. 配置三层结构（识图匹配）

`input` 模式（`["text"]` / `["text","image"]`）的优先级，从低到高：

| 层级 | 配置项 | 作用 |
|---|---|---|
| 1. 全局兜底 | `cpa.default_input_modes` | 默认 `["text"]`；写成 `["text","image"]` 即全局默认识图 |
| 2. 通配匹配 | `cpa.image_models` | fnmatch 模型名模式，命中则**叠加** `image`。`["*"]` = 全部识图 |
| 3. 单模型覆盖 | `cpa.model_overrides.<id>.input` | **最高优先级**，全开后用它单独关掉不识图的模型 |

`model_overrides` 还能覆盖 `contextWindow` / `maxTokens` / `reasoning`。

```yaml
cpa:
  default_input_modes: ["text"]
  image_models: ["*"]            # 全开识图
  model_overrides:
    some-text-only-model:
      input: ["text"]            # 单独关
    sensenova-6.8-flash-lite:
      input: ["text", "image"]  # 单独开（即使 image_models 为空）
```

**陷阱**：声明 `image` 只代表 agent 侧允许发图，**不代表上游模型真能看图**。实测过 `sensenova-6.8-flash-lite` 两条链路（官方网关 + 本地 CPA 代理）都识图；其它模型要逐个验证，否则纯文本模型收到图片会报错或答非所问。验证法：造一张写数字/画形状的图，让模型"读出数字 + 数形状"。

## 3. 中央配置要点

- **路径**：默认 `<项目根>/config/cpa-config.yaml`（按 `core/` 的上一级推导，不写死绝对路径）。拷到别处也能直接跑。用环境变量 `CPA_SYNC_CONFIG` 可覆盖。
- **不进仓库**：真实 `cpa-config.yaml` 被 `.gitignore` 排除，只带脱敏模板 `cpa-config.example.yaml`。新机器：`cp cpa-config.example.yaml cpa-config.yaml` 再填 `base_url` + `api_key`。
- **`include_models` 匹配规则**（`filter_models`）：
  - 完全相等 → 命中
  - 带 `/`（如 `sensenova/deepseek-v4-flash`）→ 取 `/` 前缀段匹配 id 前缀
  - 不带 `/` → 按**后缀**匹配
- **`strategy`**：`replace` = 全盘对齐（下游严格等于 CPA 扫出的模型，多余会被删）；`merge` = 只增不删。base_url / api_key 始终精确覆盖，不受策略影响。
- **`provider_id`**：下游作 provider 的 key（默认 `cpa`），要稳定有意义，别用随机 UUID。历史 UUID key 会在 apply 时自动迁移到 `provider_id`。

## 4. 多主机 / 跨平台

- **Windows 远程**：走 `ssh/scp`，scp 传原始字节 + 远端原子替换，避免编码问题和半写文件。**注意 win11 的 ssh 默认 shell 是 cmd**，`Get-Content` 之类 PowerShell cmdlet 不可用，用 `type` 或显式 `powershell -Command`。
- **本机 adapter**（pi / opencode / cc-switch）：直接读写本机路径，不走 ssh。
- **`hosts`** 是机器注册表（ssh 别名 + platform）；**`adapter_instances`** 声明"哪台机器上哪个文件"；**`targets`** 决定这次同步哪些下游。

## 5. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 手改的 `models.json` 被改回去了 | `strategy: replace` 的预期行为。改中央配置或 adapter，别改产物 |
| `check` 只显示"新增模型" | 目标比下游多模型时，diff 只报集合差；字段级 diff（`contextWindow`/`maxTokens`/`input`）只对**交集模型**报 |
| adapter 报"当前无配置，将新建" | `load_current` 没找到代表 CPA 的 provider 段（`name=cpa` 或 base_url 含 `:8317`） |
| om 自带模型还在 | omp 用 `scripts/omp_disable_providers.py` 写 `disabledProviders`；picoclaw 用 `scripts/picoclaw_disable_builtin.py` 删非 cpa 条目；crush 用 `option default-providers false` |
| crush 配置丢了 | `crush update-providers` 只重建 `providers.json`，不覆盖 `crushrc` —— 所以 cpa 必须写进 crushrc |
| claude/codex 风格特殊 | 同一供应商下**每个模型单独一条 provider**（`name=模型名`、`notes=cpa`），走"推翻再来"，不做增量 diff |

## 6. 加新 adapter

1. `adapters/<name>.py` 继承 `adapters.base.Adapter`
2. 实现三个方法：`load_current()`（读现状→IR）、`render(ir)`（IR→目标格式）、`write(rendered, backup=True)`（写盘+备份）
3. 注册到 `adapters/__init__.py`
4. 多主机时在中央配置加 `adapter_instances.<name>`
5. 测试：`python3 -m pytest tests/`

**diff 是基类给的**：`adapters/base.py` 的 `diff()` 已统一比较 `base_url` / `api_key`（脱敏显示）/ 模型集合 / `contextWindow` / `maxTokens` / `input`，新 adapter 白送字段级干跑能力。

**注意 remote 模式**：需要 ssh 的 adapter 用 `self.remote.read()/write()`（见 omp / openclaw / hermes），本机 adapter 直接 `open()`。

## 7. 调试与验证清单

改完配置/代码后，建议按这个顺序验证：

```bash
cd /mnt/shared/my-project/cpa-sync
python3 -m pytest tests/ -q      # 1. 单测（秒级）
./cpa-sync check <adapter>         # 2. 干跑，看 diff 是否符合预期
./cpa-sync apply <adapter> -y     # 3. 写盘（自动备份 .bak.<时间戳>）
# 4. 回滚：把 .bak.<时间戳> 拷回目标路径即可
```

- `check` 输出里 `input ['text'] -> ['text', 'image']` 即识图声明变更。
- 写完可以用 `cat`/`type` 直接看目标文件确认（win11 用 `ssh win11 "type C:\\path"`）。
